# Электронная аттестация ПД

Сайт для аттестации сотрудников Полицейского Департамента ранга «Рядовой» на игровом RP-сервере Minecraft.

Сотрудник вводит игровой ник и отвечает в свободной форме на 15 вопросов. Сайт сам сравнивает ответы с ключами, начисляет баллы и показывает итог, который удобно отправить руководству скриншотом. Аттестация сдана, если не менее 10 вопросов получили полный балл. После неуспешной попытки следующая доступна через 45 минут (срок задаётся константой `RETAKE_LOCK_MINUTES` в [src/storage/storage.ts](src/storage/storage.ts)).

Серверной части нет: сайт статический, все данные хранятся только в браузере сотрудника и никуда не отправляются.

## Установка и запуск

Нужен [Node.js](https://nodejs.org/) версии 22.13 или новее; рекомендуется текущая LTS-версия. Проект проверен на Node 26.

```bash
npm install       # установить зависимости
npm run dev       # режим разработки: http://localhost:5173
npm test          # модульные тесты логики оценки (Vitest)
npm run lint      # проверка кода (ESLint)
npm run build     # проверка типов и сборка в папку dist/
npm run preview   # посмотреть собранный сайт: http://localhost:4173
```

## Размещение на хостинге

1. Выполните `npm run build`.
2. Загрузите **содержимое** папки `dist/` на любой статический хостинг: GitHub Pages, Netlify, Cloudflare Pages, обычный веб-сервер.

В `vite.config.ts` указано `base: './'`, поэтому все пути в сборке относительные и сайт работает из любой папки, например `https://user.github.io/attestation/`. Настраивать маршрутизацию не нужно: у сайта одна страница.

Для GitHub Pages проще всего положить содержимое `dist/` в ветку `gh-pages` (или в папку `docs/` основной ветки) и включить Pages в настройках репозитория.

Двойной клик по `dist/index.html` не сработает: браузеры не загружают JS-модули по адресу `file://`. Для локального просмотра используйте `npm run preview`.

## Как редактировать вопросы, ключевые слова и синонимы

Всё содержание аттестации находится в одном файле: [src/data/questions.ts](src/data/questions.ts). Подробное описание синтаксиса есть в комментарии в начале файла.

**Одиночный вопрос** (`kind: 'single'`) — одно поле ответа:

- `text` — текст вопроса;
- `hint` — подсказка под полем (видна до сдачи, поэтому ответ в ней писать нельзя);
- `answer` — правильный ответ, показывается только после успешной сдачи;
- `check` — способ проверки:
  - `type: 'number'` — числовой ответ. В `options` перечислены правильные числа и допустимые единицы измерения (`units`). Флаг `unitRequired` делает единицу обязательной (так, «72 часа» засчитывается, а просто «72» — нет). В `aliases` перечислены фразы, которые засчитываются вместо числа (например, «лейтенант»), в `rejectPhrases` — фразы, при которых ответ не засчитывается;
  - `type: 'yes'` — утвердительный ответ: `yesPhrases` засчитываются, а при любой из `negativePhrases` ответ не засчитывается.

**Составной вопрос** (`kind: 'composite'`) — по одному полю на каждый пункт в `items`:

- `label` — формулировка пункта для показа правильного ответа;
- `match` — как искать пункт:
  - `type: 'phrases'` — пункт засчитан, если найдена любая из фраз;
  - `type: 'allOf'` — найдена хотя бы одна фраза из **каждой** группы (например, названы все три фракции); группы могут быть в разных полях;
  - `type: 'number'` — числовой пункт, правила как у одиночного вопроса.

Число полей у составного вопроса равно числу пунктов. Подписи полей («Пункт 1», «Пункт 2»…) и инструкция формируются автоматически.

**Синтаксис ключевых фраз:**

| Запись | Что найдёт |
|---|---|
| `судья` | любую форму слова: «судьи», «судей», «судьям» |
| `спец*` | любое слово, начинающееся с «спец»: «спецсредства», «специальные» |
| `=да` | только точное слово «да» |
| `9.5` | номер статьи (сравнивается точно) |
| `замест* глава` | несколько слов в этом порядке внутри одной части ответа; между ними допускается до двух других слов |

Регистр, буква «ё», знаки препинания, точки в сокращениях и дефисы не учитываются. Если перед фразой стоит «не» или «ни», она не засчитывается. Числа, записанные словами («сорок пять», «трое», «дважды»), распознаются автоматически.

Варианты записи единиц измерения («мин», «минут», «гр», «сутки», …) хранятся там же, в `UNIT_WORDS`.

Когда одна фраза пункта входит в более длинную фразу другого пункта, слова засчитываются за более длинную, то есть более точную. Поэтому «заместители глав госфракций» засчитывается только как пункт «Заместители», а «главы и заместители госфракций» — как оба пункта.

После правок запустите `npm test`. Тесты в [src/grading/grade.test.ts](src/grading/grade.test.ts) проверяют примеры ответов для каждого вопроса. Если вы меняете ключи, обновите и соответствующие примеры.

## Как устроена оценка

- Одиночный вопрос: верно — 1 балл, неверно или пусто — 0.
- Составной вопрос с *n* пунктами: все пункты — 1 балл; не менее ⌈*n*/2⌉ — 0,5 балла; меньше — 0. Пункты ищутся во всех заполненных полях независимо от порядка, повтор засчитывается один раз, одно поле может содержать несколько пунктов.
- Числовой ответ засчитывается, если в нём есть правильное число, нет других чисел (номера статей вроде «10.2.1» числами не считаются) и после числа нет противоречащей единицы («45 секунд» не засчитывается).
- Сдача — не менее 10 вопросов с полным баллом. Сумма баллов показывается отдельно и на сдачу не влияет: 9 полных и 4 частичных ответа дают 11 баллов, но аттестация не сдана.

Автоматическая проверка реализует игровые правила этого сайта. Она учитывает формы слов, синонимы и сокращения, но не может гарантированно правильно оценить любую формулировку. При необходимости её можно заменить ручной проверкой.

## Хранение данных

| Где | Что | Когда удаляется |
|---|---|---|
| `sessionStorage` | ответы незавершённой попытки (чтобы обновление вкладки их не стирало) | сразу после завершения попытки |
| `localStorage` | ник | при сбросе прогресса |
| `localStorage` | итог успешной сдачи: ник, дата, баллы, статусы по вопросам **без текстов ответов** | при сбросе прогресса |
| `localStorage` | итог последней неуспешной попытки, **тексты ответов сотрудника** этой попытки и время окончания блокировки | после следующей попытки, успешной сдачи или сброса |

После неуспешной попытки сотрудник может посмотреть свои ответы и их статусы на главной странице (блок «Ваши ответы»), в том числе после обновления страницы. Правильные ответы при этом не показываются и нигде не сохраняются. После успешной сдачи разбор с правильными ответами виден только на экране результата: в сохранённой сводке текстов ответов нет.

Повреждённые данные в хранилище игнорируются. Если срок блокировки дальше, чем через 45 минут от текущего момента (данные изменили вручную или сбились часы), он ограничивается 45 минутами.

Ответы незавершённой попытки привязаны к постоянному номеру вопроса (`id` в файле вопросов), а не к его месту в списке. Если во время попытки вопрос добавить, удалить или переставить, ответы останутся у своих вопросов.

## Оформление

Тёмно-синий «служебный терминал» в цветах полиции. На фоне — крупная полупрозрачная эмблема ПД (щит со звездой) и мягкое красно-синее свечение, которое медленно меняет яркость, без мигания. Эмблема нарисована в SVG ([src/components/DepartmentEmblem.tsx](src/components/DepartmentEmblem.tsx)), фон собран в [src/components/Backdrop.tsx](src/components/Backdrop.tsx). Картинок и сторонних ассетов в проекте нет.

- Шрифты только системные: заголовки набраны Bahnschrift (есть в Windows 10/11), на других системах — системным шрифтом.
- Если в системе включено «уменьшение движения», свечение неподвижно.
- Цвета и остальные параметры собраны в начале `src/styles/global.css`.

## Ограничения клиентской защиты

Сайт работает только в браузере, поэтому вся защита клиентская и **обходится**:

- Блокировку пересдачи и сохранённый результат можно обойти очисткой данных сайта, режимом инкогнито или другим браузером. Кнопка «Сбросить прогресс» во время блокировки недоступна, но это защищает только от случайного обхода.
- Ключи ответов (`src/data/questions.ts`) попадают в собранный JS-файл, и их можно найти в инструментах разработчика браузера.
- Данные в `localStorage` можно изменить вручную. Сайт проверяет их согласованность, но подделать результат всё равно возможно.
- Скриншот результата подтверждает только то, что показал браузер сотрудника.

Для игровой аттестации это допустимо. Если нужна настоящая защита, понадобятся сервер, авторизация и хранение ключей и результатов на сервере. Эти функции сайт сознательно не включает.

## Структура проекта

```
src/
  data/questions.ts        вопросы, ответы, ключевые фразы, синонимы, единицы измерения
  grading/                 логика оценки (чистые функции без React)
    grade.ts               оценка вопроса и попытки, пороги
    numbers.ts             числа цифрами и словами, единицы измерения
    phrases.ts             поиск ключевых фраз, отрицания
    text.ts                нормализация и разбиение ответа на слова
    stemmer.ts             приведение форм слова к основе
    grade.test.ts          тесты оценки
  storage/storage.ts       работа с localStorage и sessionStorage, проверка данных
  hooks/useRemaining.ts    обратный отсчёт до пересдачи
  components/              экраны и элементы интерфейса, фон и пиксельный значок
  utils/                   ник, ответы, форматирование
  styles/global.css        стили
```
